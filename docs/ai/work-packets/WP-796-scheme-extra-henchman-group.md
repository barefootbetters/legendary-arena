**User-Visible Surface:** cards.legendary-arena.com loadout builder, play.legendary-arena.com lobby and gauntlet

## Goal

Three schemes print "Setup: … Add an extra Henchman group (to the Villain Deck)":
- core **Negative Zone Prison Breakout** (`core/negative-zone-prison-breakout`);
- msp1 **Asgard Under Siege** (`msp1/asgard-under-siege`, a word-for-word reprint of it);
- vnom **Invasion of the Venom Symbiotes** (`vnom/invasion-of-the-venom-symbiotes`).

Today no loadout can be set up as printed. The per-player-count table allows exactly 1 Henchman group at 1–3
players and 2 at 4–5, and the loadout builder, the lobby and `Game.setup` all reject one more. Jeff hit this
building a 1-player Negative Zone match (2026-10-07).

After this packet, those three schemes **require** the base count + 1 Henchman groups at every player count
(2 at 1–3p, 3 at 4–5p), and the base count is rejected. Every surface agrees: the loadout builder and its
preview, the play lobby, `Game.setup`, and the ranked gauntlet's approved compositions for the nine affected
legs.

## User-Visible Impact

- **Loadout builder (cards):** a Negative Zone / Asgard Under Siege / Venom Symbiotes loadout shows "2 henchmen
  groups" at 1p and blocks export with 1. Every other scheme is unchanged.
- **Play lobby:** the requirement line and the create gate say 2 at 1p for these schemes. A 1-group config gets
  the existing mismatch message instead of reaching the server.
- **Match:** a 1-player Negative Zone match plays with 20 Henchman cards in the Villain Deck (2 groups × 10), as
  printed. D-24609 already counts escaped Henchmen toward its "12 Villains escape" loss for exactly this reason.
- **Ranked gauntlet:** the four 2026 Core Negative Zone legs, the three msp1 Asgard Under Siege legs and the two
  vnom Venom Symbiotes legs launch with, and qualify on, the extra group.

## Context (Read First)

**Rules.** The three schemes' setup text is the whole requirement: one Henchman group more than the player count
normally uses. A group is the usual 10 cards. The renamed-group variants ("an extra Henchman Group of 10 cards as
'Vampire Neonates'", mdns / rlmk / smhc) and the different-shape variants (xmen "10 Sentinels as extra
Henchmen", xmen Alien Brood, pttr "6 extra Henchmen … to the Hero Deck") need card-pool work, not a count. They
are named follow-ups.

**Why strict, and why now.** Jeff chose the strict rule (2026-10-07): the base count is rejected for these
schemes, exactly like Secret Invasion's "6 Heroes" (D-24337). Every Negative Zone match so far ran one group
short, which made its 12-escape loss easier to avoid than printed. Jeff is the only player with gauntlet scores,
so re-keying these legs' approved compositions mid-season costs no third party.

**Why one WP, not a pair.** The WP-524 / WP-525 precedent split enforcement from the lobby, but they shipped as
a set. Here the halves cannot be ordered:
- The requirement alone makes the nine gauntlet legs' approved compositions illegal, so "Play this leg" gets a
  400 and the legs become unqualifiable.
- The scheme-aware gauntlet compositions alone would be rejected by today's base-count engine.

The flip has to be atomic. The arena-client needs no change, so the packet touches no arena-client file.

**The gauntlet design.**
- **Authored legs (Core NZPB).** `getGauntletConfig` slices `henchmanPool` by the effective count. Each NZPB
  pool gains a third entry, `core/sentinel`: the one Core Henchman group in none of the four pools. This makes
  4–5p (3 groups) satisfiable.
- **Menu-fallback legs (msp1 ×3, vnom ×2).** The generator, which already owns the D-24199 fill rule, emits a
  per-mastermind `schemeOverrides` map for each extra-Henchman scheme in the mastermind's own set. (Core
  masterminds get one too, but their authored NZPB legs take precedence, so it is unused.) Its henchmen
  are filled for the effective count with the same rule, so it is the base composition plus the next group in
  fill order (as a set). Its villains equal the base variant's.
  - `getGauntletConfig` returns that override when no authored leg exists.
  - Seed PAR enumerates scenarios from `gauntlet-configs.json`, not from the menu. So no new competitive PAR
    scenario appears.
- **Henchman card ids are built from the bare slug** (`henchman-<slug>-NN`, `villainDeck.setup.ts` :247). The
  generator must never emit two groups that share a slug across sets (e.g. `core/doombot-legion` +
  `co2e/doombot-legion`). It asserts this for every override composition.

**Out of reach of this packet (named follow-ups):**
- the 16 NZPB PAR profiles under `data/par/profile/v1/`. They are diagnostic only (dashboard fidelity) and were
  simulated with the old composition. Regenerating needs a full 128-scenario `generate-par-profiles.mjs` run
  (no subset mode);
- `content/themes/venom-lethal-protector.json`. It already carries 0 Henchman groups, invalid against the base
  count today;
- the renamed-group and different-shape schemes above;
- the legends-board requirement list (`GauntletBoardPanel.vue` :128–137). It reads the entry-level per-mastermind
  menu (`legends.publisher.ts` :319), so it will still show the base Henchman count for the msp1 and vnom legs.
  This is display-only, and the same gap already exists for swapped Core legs.

Side effect, not a defect: `msp1/hydra-spies` starts counting as "used" in the set-coverage reveal
(`buildSetDetailsCatalog` unions over legs).

## D-24666 Content (authored at execution, Status Active)

1. **A requirement override, strict.** Schemes that print "Add an extra Henchman group" require exactly base + 1
   Henchman groups at every player count. The base count is rejected. The closed list is the three ids above.
2. **One definition.** The list and resolver live in `playerCountSetup.ts`.
   - The engine reaches them structurally and falls back to the base count without them.
   - The server projection and the loadout builder read the same resolver.
