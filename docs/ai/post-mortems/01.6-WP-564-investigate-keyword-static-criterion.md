### 4. Representation & Determinism Audit

- [x] `InvestigateCriterion` is a **data-only** discriminated union (string/number literals only)
  and `investigateLookCount` (number) / `investigateCriteria` (array of the union) are optional,
  JSON-serializable descriptor fields — no functions/closures/Maps/Sets/Dates/classes.
- [x] Deterministic: selection is **first match in look order** (no `ctx.random`, no clock);
  deck manipulation is array slices + the existing `moveCardFromZone` / `reshuffleDiscardIntoDeck`.
  The bottom-ORDER test pins reproducibility (a set-equality assertion would pass while replay
  diverges). **Sentinel `finalStateHash` + `PRE_WP080_HASH` are byte-unchanged** — the sentinel
  loadout carries no investigate hero, so `G.heroAbilityHooks` gains no new descriptor fields there
  and the whole engine suite is green.
- [x] Fails safe: a card with no `G.cardStats`/`G.cardTraits` entry yields `undefined` for the
  missing facts, so the criteria needing them do not match (no draw on a fabricated 0 — the reveal
  handler's skip-a-no-stats-card posture); an empty deck is a narrated no-op; a deferred parse form
  records an unresolved marker rather than throwing.

### 5. Mutation, Aliasing, & Reference Safety

- [x] Mutation occurs only in the handler's authorized move-execution context; the setup parser
  and `investigateCandidateMatches` mutate nothing.
- [x] `investigateCandidateMatches` returns a boolean — no reference into `G` escapes. The
  candidate object it receives is built fresh in the handler from `stats?.field` reads; no
  `G.cardStats`/`G.cardTraits` array or object is returned to a consumer.
- [x] The descriptor's `investigateCriteria` array is built fresh per ability line in
  `tryResolveInvestigateFromLine` (each `[{...}]` is a new literal), stored on a freshly-constructed
  hook — no two hooks share a criterion array, and nothing aliases a shared module const.
- [x] The handler bottoms the non-drawn cards by constructing a **new** `[...rest, ...toBottom]`
  deck array rather than mutating the peeked slice in place; `moveCardFromZone` already returns
  fresh arrays. No aliasing of a mutable `G` field into a returned value (the WP-028 class of bug).

### 6. Hidden-Coupling Detection

- [x] No engine internal exposed through a public projection — `investigate` adds no `UIState`
  field (Scope-Out: no pending choice, no projection).
- [x] `HeroKeyword` was widened by exactly one authorized member (`investigate`), with the union +
  `HERO_KEYWORDS` array + `MVP_KEYWORDS`/`HANDLED_KEYWORDS`/`NO_MAGNITUDE_KEYWORDS` kept in lockstep
  and pinned by the parity/count/handler drift tests.
- [x] **Known coupling, documented (AC-7 nuance):** the hero-mechanic ledger classifies keyword
  mechanics **by name** (`MVP_KEYWORDS.has(mechanic) → executable`; the by-hook `resolvedMarkers`
  precision exists only for parameterized composition markers). So the `investigate` mechanic reads
  `executable` for **every** hero printing it — including deferred-only heroes (daredevil-noir,
  ms-america, multiple-man, siryn, warpath, angel-noir). This is the established behaviour of every
  partially-implemented keyword and matches the ledger's own design; making `investigate` by-hook
  would be an out-of-scope change to the ledger classifier. The honest per-line signal is the parse
  tests (deferred forms record an unresolved marker, never gain the keyword) + AC-9's measured delta.
- [x] No ordering assumption beyond the explicitly-tested look order; no dependency on a non-exported
  function (the parser reuses the file's own resolvers; the handler reuses exported helpers).
