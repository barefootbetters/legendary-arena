### 4. Representation & Determinism Audit

- [x] Every intent is a plain `{ name, args }` object typed by the discriminated union over WP-806's args types, so a
  field typo is a compile error. All args are JSON-serializable.
- [x] No client randomness and no wall-clock read in the new code. Option lists are pure functions of the view.
- [x] Unknown or absent values fail safe: an empty deck binds a list with no options (probed: Tweakpane 4.0.5 does
  not throw on `options: []`, so the EC's fallback was not needed) and its empty selection submits nothing; a "Move
  card" key missing from the current lists submits nothing; the engine refuses everything else silently.

---

### 5. Mutation, Aliasing, & Reference Safety

- [x] The pane never writes the view. Tweakpane writes only the pane's own reactive `params`; the option builders
  read the view's arrays and return new arrays of new objects.
- [x] `buildMoveCardIntent` passes `source.from` and `destination.ref` by reference into the args. Both are fresh
  objects built per call by `buildCardSources` / `buildDestinations`, never view objects, so `submitMove` cannot
  reach back into the polled board.

### 6. Hidden-Coupling Detection

- [x] **Tweakpane DOM.** The tests read Tweakpane 4.0.5's class names (`tp-btnv_b`, `tp-fldv_t`, `tp-lblv_l`,
  `tp-rotv`), and the AC 9 check greps `tp-rotv` in the bundle. A Tweakpane major bump that renames them breaks the
  tests loudly, not silently; the `^4.0.5` range keeps majors out.
- [x] **List options carry no value attribute.** Tweakpane's list renders `<option>`s with text only and maps
  `selectedIndex` to `options[i].value`, so the bound param still holds the stable key. WP §D's helper text "set
  `select.value = key`" cannot work against that DOM; the tests choose the option by its text and set
  `selectedIndex`, then dispatch `change` (documented in the test header). The stable-key guarantee is still proven
  by revert proof 9.
- [x] **Nullable function prop.** WP §Locked Contract Values writes `submitMove: Function as PropType<SubmitMove |
  null>`, which `vue-tsc` rejects (TS2352). The panel uses the repo's existing nullable-prop form, `[Function, null]
  as unknown as PropType<SubmitMove | null>` (the `BillingSection` / `FriendsSection` `authToken` precedent), with
  the same `default: null`. The prop's name, type, default and optionality are as locked.
- [x] **Rebuild key.** It joins the raw villain and hero deck ids (a superset of the deck options' keys and
  positions), the source and destination keys in list order, the window state and `hasEscapeCandidate`. A reorder
  or a position shift rebuilds, so the "N. name" labels never go stale.
- [x] **Enable rule is presentation only.** The engine re-checks the operator match, the turn, the stage and open
  choices (WP-806); the click-time re-check only saves no-op submits.
