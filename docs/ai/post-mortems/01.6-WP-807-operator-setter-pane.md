### 6. Hidden-Coupling Detection

- [x] **Tweakpane DOM classes in tests.** The pane tests read Tweakpane 4.0.5's own class names (`tp-btnv_b`,
  `tp-fldv_t`, `tp-lblv`, `tp-lblv_l`, `tp-rotv`), as the WP locks. A Tweakpane major bump that renames them fails
  these tests loudly rather than silently.
- [x] **Tweakpane values `<option>`s by index.** The WP's locked input helper set a list by `select.value = key`.
  Tweakpane 4.0.5 renders each `<option>` with its list index as the value and resolves the bound value from
  `selectedIndex`, so that helper cannot select by key. The tests select a list option by its visible text (the
  label the pane shows) and fire `change`; the binding still stores the stable key, and the stable-key test and its
  revert proof (9) prove "Move card" is keyed, not indexed.
- [x] **jsdom events.** Node 22's global `Event` / `MouseEvent` are not jsdom's, and jsdom's `dispatchEvent`
  rejects them. The tests build events from `window.Event` / `window.MouseEvent`; the locked
  `dispatchEvent(new MouseEvent('click', { bubbles: true }))` is otherwise unchanged and does reach the click
  re-check (revert proof 2).
- [x] **`submitMove` prop type.** The WP locks `Function as PropType<SubmitMove | null>`. vue-tsc rejects that cast
  (TS2352: `FunctionConstructor` is not comparable to `SubmitMove | null`). The panel declares
  `[Function, null] as PropType<SubmitMove | null>`, default `null`: the same TypeScript type and the same runtime
  contract (Vue accepts a function or `null`), with a `// why:`.
- [x] **The enable rule** reads `currentStage` and `board.game.activePlayerId` only. An open choice is not visible in
  the operator view, so a click during one reaches the engine and is refused there; the closed hint says so.
