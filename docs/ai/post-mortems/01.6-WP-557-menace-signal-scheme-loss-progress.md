**A real gap found and closed during execution.** The existing
`UIProgressCounters` drift assertion pins a hand-written literal and is
accompanied by a comment claiming a `satisfies` check catches renames "at
compile time". That is **not true in this package**:
`packages/game-engine/tsconfig.json` excludes `src/**/*.test.ts` and the
package has no `typecheck` script, so **no `satisfies` in any engine test
file is ever compiled**. Combined with the new fields being optional, a
literal-only pin would have protected nothing. The new assertion is therefore
a **runtime** keyset check against a real built projection, and its comment
says why. See Notes for the follow-up this implies.

**Notes / Follow-ups:**

1. **Engine test files are never typechecked** (`tsconfig.json` excludes
   `src/**/*.test.ts`; no `typecheck` script). Every `satisfies`-based
   "compile-time drift pin" in the engine's test suite is therefore
   documentation only — including the pre-existing `UIProgressCounters` and
   `UIParBreakdown` pins in `uiState.types.drift.test.ts`, whose comments
   claim compile-time enforcement they do not get. This WP worked around it
   locally (runtime keyset assertion) but did **not** fix the general case:
   that would mean adding a typecheck script + CI step across the engine
   package, which is well outside this packet's allowlist. **Recommended
   follow-up WP:** add `"typecheck": "tsc --noEmit -p tsconfig.test.json"` to
   `packages/game-engine` with tests included, and wire it into CI. Until
   then, engine drift pins should be written as runtime assertions.
2. **The `/8` HUD lie is still live.** `PlayDesktop.vue:530` and
   `PlayMobile.vue:360` still hardcode `:scheme-twist-threshold="8"`. This
   packet deliberately did not touch it (engine-only scope); it is the
   follow-on danger-meter HUD packet's first job, and the data it needs now
   exists.
3. **Two twist-count sources coexist** — `G.counters.schemeTwistCount` and
   `G.scheme.twistPile.length`. This WP picked the loss-bearing one and
   documented why, but did not reconcile them. If they can ever diverge
   permanently (rather than mid-resolution) that is a latent fidelity bug
   worth its own investigation.
