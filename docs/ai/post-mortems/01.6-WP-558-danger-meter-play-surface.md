### 4. Representation & Determinism Audit

- [x] The new representation is **presentation-only**: numbers, a class
      string, and text. Nothing enters `G`; the engine is untouched
      (empty `packages` diff), so **no hash surface exists to move**.
- [x] Deterministic: `menaceDisplay.ts` is a set of pure functions over its
      arguments — no module state, no memoization, no clock, no randomness.
      (`src/vfx/` carries the D-24365 exemption, but this WP did not need it.)
- [x] Fails safe: NaN → 0, Infinity → 100, absent signal → renders nothing,
      absent denominator → bare count. Nothing throws.

**A bug my own test caught during execution.** The first
`menaceBarPercent` guard was `if (!Number.isFinite(menace)) return 0`, which
collapses **NaN and Infinity into the same branch** — so an over-scale value
would have rendered as an *empty* bar, the most misleading possible output
for a danger readout. The test asserting `Infinity → 100` failed, and the
implementation was fixed (NaN → 0 "unknown"; Infinity falls through to the
`>= 1` clamp → 100). The test was written before the code and was not
weakened to accommodate it.

**Notes / Follow-ups:**

1. **The WP's AC-2 was subtly wrong and was corrected at execution
   (Amendment 2).** It implied repointing the **"Twists:"** label at
   `progress.schemeLossThreshold`. That would be wrong for any scheme with a
   `resourceLossCondition`, where the threshold counts a *resource*, not
   twists — Negative Zone's is 12 escaped villains, so the HUD would have
   rendered `Twists: 3/12`, replacing one wrong number with another. The
   twist readout is now a **bare count**, and the scheme-aware ratio lives on
   the meter under a label that matches what it counts. AC-2's intent (the
   denominator is the projected one, never a hardcoded 8) is preserved and
   proven by a `DangerMeter` unit test rendering `4/5`.
2. **`:mastermind-tactics-total="4"` remains hardcoded** in both parents —
   the same pattern that produced the `/8` defect. It needs an engine-side
   projection before it can be fixed, so it is its own packet. Recorded in
   the WP's §Notes and carried here so it stays visible.
3. **Two `?? 0` fallbacks** exist in the component for
   `schemeLossProgress`/`menace` when the guard has already established the
   signal is present. They are defensive and harmless, but a reader could
   mistake them for a defaulting policy; the `hasMenaceSignal` type guard is
   the real gate.
