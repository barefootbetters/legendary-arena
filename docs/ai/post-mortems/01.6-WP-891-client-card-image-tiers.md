### 5. Mutation, Aliasing, & Reference Safety

- [x] `CardImage`'s `sources` is a computed from the prop and one boolean (`hasTierFailed`); a `watch` on `imageUrl` resets the boolean before render, so a recycled component (a prompt list re-keyed in place) never shows a previous card's original.
- [x] The VFX `onerror` clears itself first and is attached only while a tier is in use, so a failing original cannot re-enter it (copilot Mode 22). A test asserts `art.onerror === null` after the fallback.
- [x] The prefetch fallback uses a fresh `Image`, never the failed one (the fake has no `removeAttribute`, and a real element would keep reselecting from its `srcset`).

---

### 6. Hidden-Coupling Detection

- [x] **Scoped CSS still reaches the image.** Each site's class (e.g. `.card-tile__image`) now sits on `CardImage`'s root `<img>`, which Vue stamps with the parent's scope id, so every existing scoped rule still applies. No style moved.
- [x] **Parent `@error` listeners.** `emits: ['error']` keeps a parent listener off the `<img>`; without it CardTile's name tile would show on the first tier failure (the EC's first failure smell). The CardTile test asserts the tile appears only after two errors.
- [x] **jsdom event realm.** A Node `new Event()` is rejected by jsdom's `dispatchEvent`; the VFX test uses `window.Event`. A thrown test that skipped `unmount()` left an overlay mounted and broke a later hint test, which is how the realm issue surfaced; both pass once the event is built in the jsdom realm.
- [x] **Airplane mode.** A 1x board now requests `thumb` while the planned offline download is `phone`; named as a D-24848 follow-up and on `wiki/airplane-mode.md`.
