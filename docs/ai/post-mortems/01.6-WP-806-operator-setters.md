### 4. Representation & Determinism Audit

- [x] `G.operatorSetAside` holds `CardExtId` arrays only, JSON-serializable, written only by
  `operatorSetSupplyCount` and absent until its first decrease (tests assert no key on a fresh operator match
  and no `setAsideCounts` key on its view). Normal matches never write it, so both hash oracles are byte-identical.
- [x] Deterministic: same `G` + args on two clones deep-equal for all six setters. Setter 3 picks the first

  equal increase restores the order (tested).
- [x] Unknown values fail safe: every invalid union member, non-integer, out-of-range count or HQ space,
  foreign player id and absent card returns `void` with `G` untouched (deep-equal to a `structuredClone`).

### 6. Hidden-Coupling Detection

- [x] **Gate scope.** `isOperatorChoiceOpen` composes `hasAnyPendingChoice` with the three fields it does not
  cover. A future block-all choice added to `hasAnyPendingChoice` is picked up automatically; one added outside
  it (the `pendingHeroChoice` shape) must be added here too.
- [x] **Undercover mirror.** `PlayerZones.undercover` mirrors `victory` for scoring. R2 / R3 from a Victory Pile
  move the `victory` copy only, so an Undercover card moved that way leaves a stale `undercover` entry. Accepted:
  an operator match is never scored (D-24689 §3) and no test or live-verify relies on it.
- [x] **No rescue triggers** for Bystander → Victory Pile and Sidekick → discard (WP §Limitations); the log
  names the route.
- [x] **Inherited after-move hooks.** The tests call the moves directly, so `turn.onMove` / `endIf` do not run
  here (WP §Limitations); live behavior is verified under WP-807.
