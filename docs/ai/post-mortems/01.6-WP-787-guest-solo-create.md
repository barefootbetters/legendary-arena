### 6. Hidden-Coupling Detection

- [x] **Featured-table duplication.** The table is duplicated from WP-785's client `FEATURED_TABLE`
  on purpose, so the server does not import from the client. Test 10 proves it is legal. The client
  adoption WP (WP-788) owns the equality check between the two.
- [x] **Native response shapes.** The route reads `matchID` and `playerCredentials`, the same fields
  autoplay and `mintGuestSeat` read. A boardgame.io bump that renamed them would break all three
  together, and the local smoke exercised the real shapes.
- [x] **Key-source ordering.** The key-source log runs before the rate check. Test 5 pins that it
  fires once across an allowed request and a 429.
- [x] **Capacity is soft under concurrency.** The cap is checked, then recorded after the join, so N
  truly simultaneous requests at 199 can all pass. This is accepted in WP §Limitations; the per-key
  bucket and the reaper bound it.

### 9. Forward-Safety Questions

- **Survives refactors?** Yes. It is server-only and reaches the engine through the public lobby API.
- **Replay/debugging?** Yes. The match is an ordinary bgio match; a finished one is harvested like any
  other.
- **Upstream data removed?** A missing card id fails native create with a 400 that is passed through;
  test 10 fails first in CI.
- **Can it influence gameplay unintentionally?** No. It changes no rule and writes no domain row; a
  guest match is Casual.
- **Stable contract?** Yes for the route shape and the helper's two exports. One open item: **the
  key source is unverified in production.** If Render's edge strips or does not set
  `cf-connecting-ip`, every caller shares the `request.ip` bucket, and 5 creates a minute becomes the
  global rate. The mitigation is the D-24026 live check (WP DoD) and the D-24635 §4 follow-up. That
  follow-up moves the analytics and join-as-guest limiters onto this helper, and should wait for
  this result.
