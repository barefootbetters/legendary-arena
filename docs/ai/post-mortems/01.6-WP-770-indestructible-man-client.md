### 6. Hidden-Coupling Detection

- [x] **The plain Fight gate.** A top arm in `gateForFight` returns the lock (or the vanquished reason) whenever `shuffleFight` is present. That one arm keeps the card disabled and non-interactive, hides Excessive Violence through `showEvFight`, and keeps a stage or "Needs N attack" reason off the button. The `onFight` guard stops a direct call too. This is the STATUS WP-768 follow-up "put the lock reason ahead of the client cost gate".
- [x] **The heal lock.** The tile calls `useTurnActions(stage, isViewerTurn)` without the heal flag, so `gateForShuffleFight` adds `healLockGate` as `gateForFight` does (the 01.7 round-1 catch).
- [x] **The close watch.** It keys on `isFightPossible()`: the shuffle gate for him, `gateForFight` otherwise. For every other Mastermind this reduces exactly to the old `gateForFight().allowed && !isGameOver`, so the existing Enigma tests pass unedited. Revert proof (f) shows that the old key never fires in the branch.
- [x] **The Enigma hand-off.** The engine requires `enigmaGuess` on the shuffle-fight and settles it after the shuffle, so the chooser's pick rides `enigmaGuessFight.shuffleAssassinIds`. `onEnigmaGuess` builds the three payloads with `if / else if / else`.
- [x] **The stand-up lift.** `--fortified` is on whenever `fortifiedReason` is set, which covers every state in which the chooser can open (the IM lock or a guard reason), so the lift never fires under the dialog. The chooser is teleported out of the board anyway.
- [x] **Pending choices.** The tile has no pending-choice props. During a pending choice the shuffle button can be enabled and the engine ignores a click, exactly as Fight and Wound do. This is the accepted posture (WP-770 Constraints).
