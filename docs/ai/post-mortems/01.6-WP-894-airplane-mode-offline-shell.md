### 6. Hidden-Coupling Detection

- [x] **Shared entry chunk and late facade deletion (found in AC 2).** The WP's scaffold said the input key `index` keeps the live entry named `index-*.js`. At HEAD two HTML entries make `src/main.ts` a shared chunk named `main-*.js`, plus empty per-entry facade chunks that Vite's build-html plugin deletes in its own `generateBundle`, after normal plugins. The first build listed both deleted facades in `precache.json`, so every install would have failed on the SPA fallback. Fixed: the plugin runs `enforce: 'post'`, and `chunkFileNames` names the chunk holding `src/main.ts` `index-*.js`, which keeps `/` on its file name and keeps `scripts/check-connections.mjs` (it finds the live bundle by `assets/index-*.js`) matching. The shared stylesheet is now `main-*.css`; nothing reads that name.
- [x] **vm realm.** Objects created inside the worker's vm context (the `init` passed to `fetch`) fail `deepStrictEqual` against main-realm literals; the suite JSON round-trips them, as the WP warned.
- [x] **Browser pane can't run service workers.** The desktop app's browser pane fails every `register()` with the same "unknown error", including for a 404 and a wrong-MIME script. Spawning the installed Chrome from this session fails with `EPERM`; the repo's Playwright Chromium runs. AC 3 / AC 4 and AC 7's browser part use headless Chromium on a persistent profile.
- [x] **Leaving scope offline.** The endgame **Back to Lobby** (`PlayViewport` → `window.location.assign('/')`) and the brand header's links leave `/offline/`; offline they land on the browser's error page. Out of this packet's scope (no `PlayViewport` change); recorded in D-24851.
- [x] **`Local()` master map.** Each **New game** adds a master to boardgame.io's module-level map (D-24842 post-mortem §6). Not fixed: the WP locks the `localSpike*` modules unchanged. Recorded in D-24851.
