### 4. Representation & Determinism Audit

- [x] One physical card is one `inPlay` entry (the face-a id). Face b never enters a zone, so the
  duplicate-id invariant, cleanup and the UI's in-play count stay physical (AC-8).
- [x] Both new fields are optional, lazy, carried by `carryConversionFlag` and dropped by
  `resetTurnEconomy`. There is no new top-level `G` field. A game without Penumbra serializes
  byte-identically, and the sentinel `finalStateHash` and replay fixtures were not re-pinned.
- [x] Face order is fixed to data order (`sides[0]` then `sides[1]`). There is no RNG and no new
  choice.
- [x] `playedCardIdsThisTurn` returns a fresh copy of `inPlay` when the ledger is absent or empty,
  or when `turnEconomy` is missing (the `heroConditionHoldsForInPlay` slice). Every non-Penumbra
  read is therefore unchanged.

### 5. Mutation, Aliasing, & Reference Safety

### 6. Hidden-Coupling Detection

- [x] **Marker placement.** The ledger entry is written after face a's hooks and before face b's,
  so face a cannot see face b. AC-6 pins this: face a's draw must not fire.
- [x] **Self-exclusion.** Self-exclusion still compares ids (`playedCardId === triggeringCardId`).
  Face b fires under its own id, so it excludes itself and sees face a. A test pins that face b
  never counts itself.
- [x] **Unlisted read.** `ui/uiState.build.ts` ~L1595, the KO-reward in-play target projection,
  is on neither WP list. It is a target / UI read (it mirrors the listed `heroEffects` ~L2745
  optional-KO eligibility), so it stays raw and nothing was guessed. It is reported to the
  operator.
- [x] **Cross-seat reads.** Villain effects read every seat's `inPlay` against the active player's
  `turnEconomy` ledger. Instance ids are unique, so only the active player's marked card can
  expand.
