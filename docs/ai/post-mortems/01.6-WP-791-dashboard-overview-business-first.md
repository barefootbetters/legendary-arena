### 6. Hidden-Coupling Detection

- [x] **Feed caps.** `MATCH_FEED_LIMIT = 50` / `PLAYER_FEED_LIMIT = 100` mirror the server's
  `MATCH_LIST_LIMIT` / `PLAYER_LIST_LIMIT` (D-24169). If the server raises a limit, the `"+"` marker
  turns on later than it should until these follow. A `// why:` names the source.
- [x] **ApiError classification** reads `code` / `retryable` as `normalizeError` sets them. A change to
  that normalizer changes the Server card's red-vs-dash split; the branch tests pin the current
  mapping.
- [x] **Infra month.** Costs treat the month-to-date actuals as a full month. That is valid only while
  `INFRA_COST_ACTUALS_AS_OF` is a month-end date (`// why:` in the widget). A mid-month refresh of the
  actuals would understate Costs and lengthen Runway.
- [x] **Two "mock" fields on DR.** The envelope `source === 'MOCK'` (dev mock mode) is checked before
  the payload's `source === 'mock'` (the production placeholder), because the mock factory sets both.
  Tests pin each branch.

### 9. Forward-Safety Questions

- **Survives refactors?** Yes. The math is in one pure module, and the widgets only render.
- **Upstream data changes?** If `revenue_30d` is missing or the KPI fetch fails, Revenue, Royalties,
  Net, and Runway read `—`, never $0. If a feed shape changes, the count drops to the parseable rows.
- **Can it mislead the operator?** The known undercounts are labelled. Engagement shows `"+"` on capped
  feeds and "Finished with a winner" for ties. The DR card cannot show green until a real drill feed
  exists.
- **Stable contract?** The storage key and record are versioned. A server-stored, cross-device record
  is the deferred follow-up named in D-24653 §3; it would read this record once to migrate it.
